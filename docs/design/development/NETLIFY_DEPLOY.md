# Deploy Sound Trainer v0.7.0 to Netlify

The repository contains **readable development source**. The public site should serve only Vite's compiled **`dist/` output**, which is minified and excludes the source maps and tests.

> The new app has four built-in sound-sequence drills: Trigger; Rack slide → Trigger; Magazine change → Trigger; and Draw from holster → Magazine change → Trigger. Sound classification is experimental and a detected sequence is not evidence of physical technique or safety.

## Option A — recommended: GitHub → Netlify (automatic deployment)

This connects to your intended GitHub repository, **`matosaru/dryfire`**. Netlify builds and deploys automatically for future pushes.

1. On a computer, unzip the **source** ZIP so the folder contains `package.json`, `index.html`, `netlify.toml`, `src/` and `public/`. Do **not** upload `node_modules/` or `dist/` to GitHub.
2. If the GitHub repository exists and is empty, open a terminal in the unpacked project directory and run:

   ```bash
   git init
   git branch -M main
   git add .
   git commit -m "Add initial four sound-sequence drills"
   git remote add origin git@github.com:matosaru/dryfire.git
   git push -u origin main
   ```

   **If the repository already contains commits**, clone it instead, copy the updated project into the clone, inspect the diff, and commit and push. Do not run `git push --force`. Use an SSH key authorized for the `matosaru` account, or use HTTPS and your normal GitHub credentials.

3. Sign in to [Netlify](https://app.netlify.com/), choose **Add new project → Import an existing project → GitHub**, and authorize the GitHub account that can access `matosaru/dryfire`.
4. Pick **`matosaru/dryfire`**, production branch **`main`**, base directory **project root**, build command **`npm run build`**, publish directory **`dist`**. The included `netlify.toml` sets the command, directory, and **Node 22** automatically.
5. Select **Deploy** and wait until Netlify displays **Published**. Open the site's `https://...netlify.app` address to verify it.
6. For future releases, edit readable files under `src/`, commit and push to `main`. Netlify builds a new minified `dist/` for each push.

> If Netlify reports a dependency or build error, check its deploy logs. The `dist/` directory must be generated by Vite, not uploaded as source code. This release's build was not executed in the preparation environment because npm could not reach the registry.

## Option B — without GitHub: upload the source project to Netlify Drop

Netlify's [current Drop guide](https://docs.netlify.com/start/quickstarts/netlify-drop-quickstart/) says a signed-in user can upload a **source project that requires a build**. Netlify detects the framework and runs its build. This route is more convenient on a phone than building locally, but the exact file picker interface can vary.

1. Save the source ZIP in Files on your iPhone; unzip it using Files if Netlify's upload picker does not accept the ZIP.
2. Open Safari, sign in at [app.netlify.com](https://app.netlify.com/login), then open [Netlify Drop](https://app.netlify.com/drop).
3. Choose the unzipped **source project folder** (containing `package.json` and `netlify.toml`) or select the ZIP if the upload control offers ZIP support.
4. Verify Netlify runs `npm run build` and publishes `dist/`. If it publishes unbuilt files directly, this was a manual/static upload—not a successful Vite deploy; switch to Option A or Option C.
5. Open the new HTTPS URL and confirm the app loads. The service is hosting your front end; learned examples remain in the device's IndexedDB, not on Netlify.

## Option C — manually upload a minified `dist/` folder

On a computer with Node.js **22+**:

```bash
npm install
npm run test:smoke
npm test
npm run build
npm run verify:dist
```

Then log into [Netlify Drop](https://app.netlify.com/drop) and drag **only the generated `dist/` folder** onto the upload area. This is the safest manual route for preserving source secrecy through minification. It will not automatically update when GitHub changes; you must build and upload the folder again.

## Add to iPhone Home Screen

1. Open the hosted `https://...netlify.app` URL in **Safari on the iPhone**.
2. In Safari's **Share** menu choose **Add to Home Screen → Add**. If the option is not immediately visible, scroll the Share actions.
3. Launch the app from its new icon, allow microphone access, and acknowledge the in-app safety checklist.
4. In **Learn**, record at least **3** labeled examples for each of the four categories (8–10 recommended). Keep the microphone position and surrounding noise reasonably stable.
5. Open **Listen → Training mode**, select a drill and tap **Start continuous listening**. The app tracks recognized sequence steps, repeats and out-of-order/unknown events without intentionally ending the foreground listening session.

**iPhone limits:** the mic is available only while the app remains in the foreground; iOS may interrupt audio for calls or system events. Recognition accuracy and fast multiple-action segmentation are not validated on a physical iPhone. Overlapping sounds can be merged. Results and examples are browser-device-local and are not automatically synced between Safari and an installed Home Screen app. Export a backup before clearing site data, changing devices or reinstalling.

## Troubleshooting

- **404 or blank page:** Inspect the deploy log; ensure Vite build succeeded and `dist/index.html` is the publish entry, not source `index.html`.
- **No microphone:** Use HTTPS, Safari microphone permission, and ensure another app is not occupying the mic. Check the app's device-status text.
- **All detections show Unknown:** Relearn balanced examples for all four sounds using the same device; the classifier is heuristic and does not report calibrated probabilities.
- **Stop after one event:** Make sure you tapped **Start continuous listening**, not **Single sound test**; the latter is one-shot by design. Check foreground status and the microphone-active indicator.
- **Changes not visible:** Reopen/refresh the site after a new Netlify deploy; the service worker cache is versioned and should update on next navigation.
