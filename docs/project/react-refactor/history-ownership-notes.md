# History ownership notes

Implementation notes within the approved P5 scope, not new product requirements. Keep [plan.md](plan.md) as the execution checklist.

- `main.js renderHistory` owns the request token and selected-gun ID. It reads events, awaits `sessionController.renderSavedSessions(gunId,isCurrent)`, checks ownership again, then renders progress, evaluation and recognition rows. Preserve these checks around every async boundary and any presentation callback.
- `sessionController.renderSavedSessions` reads records and checks both current gun and request predicate before painting. Expose a presentation port for typed saved-session cards without moving capture, saving, record ownership or practice/sequence navigation into UI. Preserve the existing native fallback until P7.
- `optional/progressView.js` caches the exact group select, range select and content node and owns their listeners/filter state. Retain this independent section during the parent-page handoff. Then migrate its content through a typed renderer while retaining controls and filter state. Keep graph implementation inside the private-only optional dependency graph; do not import graph code into the public History page or eagerly load React at private startup.
- `maxResults` is a native number input with approved constraints and a live `change` listener. Incomplete numeric text can have `value === ''` while the browser retains a different invalid draft. Preserve the exact input node, hint and native constraint state rather than reconstructing a draft from `.value`. Profile-owned limit updates remain explicit.
- Recognition rows contain date, score, optional historical sequence text and a verification select. Preserve recorded/custom historical titles, the existing score fallback, unknown handling, labeling semantics and selected-gun scope. Characterize before changing data or action ownership; cached UI must not introduce stale cross-profile results/actions.
- Evaluation uses `evaluateEvents` and a specific actual/predicted class order, caption and correct-cell rule. Reuse pure evaluation logic and compare typed presentation with frozen native output, including empty/unverified histories.
- Clear recognition history and clear saved sessions are separate confirmed operations with different retention scopes. Preserve both outcome messages and refresh saved lists/statistics/graphs through the typed owner. Existing Free saved sessions/text and Full-only graphs must stay separate.

Verify source/DOM/CSS parity, both themes/editions, restored older data, clear scopes, selected/unselected profile changes, filters, invalid numeric drafts, stale async reads, saved-review navigation and installed offline loading. Retire obsolete sources only after their final consumer migrates. Final performance acceptance remains P7 against the original baseline.
